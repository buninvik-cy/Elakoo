# ELAKOO - инструкции для агента (handoff v1.1)

Вложения: `ELAKOO_Website_TZ_and_Schemes_v1_1.pdf` (визуальное ТЗ на 12 страниц), `ELAKOO_Website_TZ_v1_1.md` (подробное ТЗ), PNG-wireframes, `elakoo.config.example.json` (конфигурация плейлистов).

## Что нужно сделать
Реализовать адаптивный светлый видеокаталог Elakoo по приложенным схемам. Никакой LMS, курсов и кабинетов. Только A2/B1, по 4 раздела на каждый уровень (Speaking Part 1/2/3, Writing), всего 8 публичных разделов. Источник контента - YouTube. Видео можно смотреть на сайте и открыть на YouTube. Должна работать контактная форма.

## Ключевое уточнение v1.1
- **Videos:** обычные ролики, включая горизонтальные видео, смонтированные из множества отдельных Shorts. Карточки 16:9.
- **Shorts:** самостоятельные вертикальные видео. Карточки 9:16.
- **Главная и разделы:** сперва Full Videos, ниже отдельная полоса Shorts.
- **Общий каталог `/videos/`:** две вкладки Videos (по умолчанию) и Shorts, фильтры уровня и части экзамена.
- **Не смешивать Shorts и Videos** в одной сетке.

## Как понять, что показывать
1. Получить содержание 8 тематических плейлистов. Они задают уровень и часть экзамена.
2. Если владелец создаст 9-й технический плейлист `All Shorts`, получать из него video IDs. Принадлежность к этому индексу определяет `format=short`. Он НЕ создаёт страницу и не меняет 8 разделов сайта. Каждый Short владелец добавляет и в тематический плейлист, и в All Shorts.
3. Если 9-й плейлист не создан, использовать `formatOverrides` и простую очередь неразмеченных роликов. Без маркировки стандартный YouTube API не гарантирует точный тип Shorts.
4. Priority: override > Shorts index > video by default (только если index есть). Если index нет и override нет - unknown, для проверки.
5. Новые видео подтягивать автоматически, хранить последний успешный JSON кэш.
6. Не пытаться определить Shorts по длительности в 60 секунд, дате или названию.

## Компиляции
Обычное длинное видео из собранных Shorts - самостоятельное Video. Отдельные Shorts остаются в Shorts. Сопоставление `longId -> [shortIds]` необязательно в MVP, но модель данных должна поддерживать его. Не угадывать связь автоматически.

## До начала настоящего деплоя запросить у владельца
- 8 playlist IDs и проверенную ссылку канала `elakoo_greek`;
- будет ли 9-й Shorts index, либо владелец выбирает ручную разметку;
- реальные бренд-файлы, домен и почту для формы.

Не заполнять продакшен случайными YouTube ID и не подменять функциональную контактную форму кнопкой mailto. Реальные токены и ключи только в серверном окружении.

Сверить 16 критериев в разделе 13 основного Markdown ТЗ, особенно пагинацию playlistItems, различение Video/Short, мобильные Shorts, контактную форму и отсутствие фальшивого контента.

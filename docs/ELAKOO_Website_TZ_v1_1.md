# ELAKOO - техническое задание на сайт-каталог YouTube-видео
**Версия:** 1.1 | **Дата:** 19.11.2026 | **Статус:** согласованная концепция для передачи агенту на дизайн, верстку и разработку

## 1. Идея проекта и границы MVP
ELAKOO - минималистичный видеокаталог для подготовки к экзамену по греческому языку. **Только A2 и B1**, по 4 раздела на каждый уровень: Speaking Part 1, Speaking Part 2, Speaking Part 3 и Writing. Материалы публикуются в YouTube-канале `elakoo_greek`. На сайте их можно просматривать через официальный встроенный плеер либо открыть оригинал на YouTube. Сайт не хранит видеофайлы.

**Важно:** это НЕ онлайн-школа, не курсы, не последовательность уроков. Не нужны кабинет, тесты, упражнения, домашние задания, рейтинги, прогресс, платный доступ или подмена просмотра через YouTube. Отдельно показываются **Videos** (горизонтальные обычные ролики, в том числе длинные видео-компиляции из Shorts) и **Shorts** (самостоятельные короткие вертикальные ролики).

Визуальное направление - простая сетка и навигация Dreaming Spanish, собственная айдентика Elakoo, светлая тема, белые поверхности, синие акценты, фирменные превью и логотип.

## 2. Восемь разделов - восемь основных плейлистов
Каждая страница раздела соответствует **одному конкретному YouTube playlist ID**.

| Уровень | Раздел | URL сайта | YouTube источник |
|---|---|---|---|
| A2 | Speaking Part 1 | `/a2/speaking-part-1/` | `REPLACE_A2_S1` |
| A2 | Speaking Part 2 | `/a2/speaking-part-2/` | `REPLACE_A2_S2` |
| A2 | Speaking Part 3 | `/a2/speaking-part-3/` | `REPLACE_A2_S3` |
| A2 | Writing | `/a2/writing/` | `REPLACE_A2_W` |
| B1 | Speaking Part 1 | `/b1/speaking-part-1/` | `REPLACE_B1_S1` |
| B1 | Speaking Part 2 | `/b1/speaking-part-2/` | `REPLACE_B1_S2` |
| B1 | Speaking Part 3 | `/b1/speaking-part-3/` | `REPLACE_B1_S3` |
| B1 | Writing | `/b1/writing/` | `REPLACE_B1_W` |

Не добавлять A1, B2, Reading, Listening. Пункты A2 и B1 в меню могут вести к соответствующим секциям на главной без создания отдельных страниц уровня.

## 3. Ключевая логика Videos / Shorts
**Плейлист определяет тему и уровень, а не обязательно формат.** Если один плейлист содержит обычные видео и Shorts, одного playlist ID недостаточно для безошибочного разделения. В стандартном YouTube Data API нет официального свойства `isShort`. Нельзя полагаться только на длительность (Shorts могут длиться до 3 минут), заголовок или соотношение превью.

**Рекомендуемое решение, если владелец согласен добавить ОДИН технический плейлист:**
- Сохранить **8 основных плейлистов**, как согласовано. Они определяют уровень и раздел, доступны пользователю с сайта.
- Создать дополнительный плейлист YouTube **ELAKOO - All Shorts** с собственным `shortsIndexPlaylistId` (9-й плейлист служебный, **не является девятым разделом сайта**).
- Каждый Short добавлять **в два плейлиста**: тематический из восьми и общий индекс Shorts. Каждое обычное длинное видео - только в тематический. Тогда сайт точно распознает Shorts по пересечению идентификаторов, не используя эвристику и не требуя правок сайта после публикации.
- Служебный плейлист не показывать в навигации, не выводить в каталог материалы без принадлежности к одному из восьми тематических плейлистов.
- При синхронизации приоритет ручного исключения (`formatOverrides`) выше, чем попадания в служебный Shorts-плейлист: можно поправить редкую ошибку или пограничный случай.

**Совместимый режим БЕЗ дополнительного плейлиста (если принципиально оставить ровно 8 на YouTube):** хранить `videoId -> short|video` в небольшом JSON-файле или простой панели настройки. Новые идентификаторы после синхронизации помечать как `Needs classification`, а не считать каждый короткий ролик автоматически Short; агент должен обеспечить простой способ подтвердить формат. До подтверждения новые материалы не должны появляться в неправильной группе (возможен временный список проверки в конфигурации). Контент не должен пропадать без уведомления администратора. Оба режима поддержать одной моделью данных.

**Альтернатива, но не рекомендуется на старте:** 16 отдельных плейлистов (Videos и Shorts для каждого из 8 разделов). Это лишняя работа с каналом.

### Примеры поведения
- Short добавлен в `A2 Speaking Part 1` + `ELAKOO - All Shorts` -> показывать в A2 / Speaking Part 1 / Shorts и Latest Shorts.
- Длинное видео-компиляция добавлено в `A2 Speaking Part 1`, но отсутствует в Shorts index -> показывать в A2 / Speaking Part 1 / Videos и Latest Videos.
- Ролик есть только в служебном Shorts index и ни в одном тематическом -> **не отображать** на сайте.
- Один YouTube ID добавлен в два тематических плейлиста -> показывать в обеих страницах разделов, но в общем каталоге только один раз с метками категорий.
- Удалён из тематического плейлиста -> после следующей синхронизации исчезает из этой категории; если не осталось ни одной категории, исчезает с сайта.
- Неизвестный формат при режиме 8 плейлистов -> пометить для классификации, не выдавать за обычное длинное видео только из-за отсутствия метки.

## 4. Карта сайта и переходы
- `/` - главная: Header, Hero, 2 блока A2/B1, Latest Videos, Latest Shorts, About Elakoo, компактная форма Contact, Footer.
- `/videos/` - общий каталог: **две вкладки Videos (по умолчанию) / Shorts**, фильтры Level (All/A2/B1), Section (All/Speaking Part 1/2/3/Writing), сортировка. Внутри вкладок не смешивать формы карточек.
- 8 страниц из раздела 2 - **сначала блок Full Videos**, ниже **отдельный блок Quick Practice / Shorts**. Оба содержат ВСЕ материалы соответствующего формата, с Load more при длинных списках.
- `/about/` - краткий проект Elakoo; допускается якорь главной плюс доступный URL.
- `/contact/` - форма обратной связи, тот же компонент на главной.
- `/privacy/` - обработка персональных данных формы и информация о встраивании YouTube.
- Переходы на конкретное видео, конкретный YouTube-плейлист и YouTube-канал.

## 5. Главная: порядок блоков
1. **Header**: логотип Elakoo, A2, B1, All Videos, About, Contact, YouTube. На телефоне меню-бургер.
2. **Hero**: бейдж `LEARN GREEK WITH ELAKOO`; H1 `Prepare for your Greek exam`; текст `Free A2 & B1 Greek exam video practice. Watch here or on YouTube.`; кнопки `Explore videos` и `YouTube channel`.
3. **Exam sections**: две крупные колонки A2 и B1; в каждой 4 карточки Speaking Part 1, 2, 3, Writing. Каждая карточка ведет на тематическую страницу, не на внешнюю ссылку.
4. **Latest Videos**: 6 последних **обычных** видео из 8 плейлистов; оригинальные 16:9 превью, заголовок, уровень, раздел, длительность и переход к просмотру на сайте. Ссылка `All videos` открывает `/videos/?format=video`.
5. **Latest Shorts**: 6-8 последних **вертикальных** Shorts из тех же 8 плейлистов; карточки 9:16. Ссылка `All Shorts` открывает `/videos/?format=short`.
6. **About Elakoo**: 2-3 предложения и ссылка About/YouTube.
7. **Contact**: простая рабочая форма Name, Email, Subject, Message.
8. **Footer**: права, контакты, YouTube, Privacy.

Видео-компиляция из десяти Shorts на главной **не дублируется как Short**. В Latest Videos она занимает одну карточку; исходные Shorts по отдельности появляются в Latest Shorts.

## 6. Страница одного раздела: шаблон x 8
- Breadcrumb `Home / A2 / Speaking Part 2`; H1 `A2 · Speaking Part 2`, короткое описание и кнопка `Open playlist on YouTube`.
- **Видео-плеер**: встроенный официальный YouTube iframe загружается только при выборе карточки / нажатии Play. По умолчанию превью; без автоматического старта. Для Short использовать вертикальный контейнер с ограничением высоты и возможностью открыть в YouTube.
- **Full Videos**: основная сетка горизонтальных 16:9 карточек, сюда относятся и длинные видео-подборки. Показывать все материалы с пагинацией или Load more по мере роста.
- **Shorts · Quick Practice**: отдельная горизонтальная лента/карусель превью 9:16, при необходимости кнопка `Show all Shorts` для раскрытия полной сетки. Shorts ни в коем случае не смешивать по высоте с горизонтальными видео.
- Внутри раздела порядок карточек - заданный в исходном тематическом плейлисте (опция Newest first может быть добавлена). При переходе из Latest Videos/Shorts и общего каталога выбранный ролик открывается через `?v=VIDEO_ID`.
- В **длинном видео-компиляции** предусмотрена опциональная секция `Individual Shorts from this video` (этап 2): только если владелец заполнил сопоставление IDs; не пытаться выводить состав по названию или автоматически резать ролик.
- Для пустого формата показывать `New videos are coming soon` / `Shorts are coming soon`; другой формат продолжает отображаться.
- Кнопка просмотра на YouTube должна быть у выбранного ролика, а ссылка на оригинальный тематический плейлист - вверху страницы.

## 7. Общий каталог `/videos/`
- Вкладки **Videos** / **Shorts** (не смешанная общая сетка). По умолчанию Videos.
- Фильтры по A2/B1, части экзамена, сортировка Newest; параметр URL `format=video|short`, `level=a2|b1`, `section=speaking-part-1|speaking-part-2|speaking-part-3|writing`.
- Видео: карточки 16:9, сетка 3-4 в ряд desktop, 1-2 mobile. Shorts: 9:16, 4-6 desktop, 2-3 mobile.
- Поиск по заголовку опционален, без сложного полнотекстового движка.
- Дедупликация по `youtubeId` только в общем каталоге и на главной (если несколько тематических плейлистов). Показывать метки всех категорий.
- Длинный список выдавать порциями (18-24 карточки / Load more) с доступной навигацией и сохранением фильтров в адресной строке.
- Каждая карточка позволяет посмотреть ролик на сайте и открыть оригинал на YouTube.

## 8. YouTube Data API: интеграция, синхронизация и контроль формата
**Источник истины для принадлежности** - 8 тематических playlist ID, для определения Shorts - опциональный 9-й индекс либо ручная конфигурация. Не искать ролики по словам `A2`, `B1`, `Shorts` в заголовке.

- `playlistItems.list`: обойти **все страницы** через `nextPageToken` (`maxResults` до 50), для каждого playlist ID получить `videoId`, позицию, membership.
- `videos.list`: пакетно получить название, превью, `publishedAt`, `duration`, доступность / разрешение на embed там, где возвращается, и другие метаданные.
- Периодическая синхронизация на сервере / build job (ориентир раз в 3-6 часов) + ручная команда `Sync now` для разработчика/администратора. Не вызывать YouTube API из браузера на каждый просмотр. Ключ хранить в секретах окружения с ограничениями.
- Если настроен `shortsIndexPlaylistId`, раз в ту же синхронизацию получить **все ID** индексного плейлиста (с пагинацией), определить `format='short'` по membership. Если ролик отсутствует - `format='video'`, если нет override.
- Если нет index playlist, использовать `formatOverrides` и список ожидающих классификации. При обновлении вывести администраторам отчет об обнаруженных новых неопознанных ID.
- Приоритет: **`formatOverrides` > Shorts-index membership > Video by default при наличии индекса**. Без индекса и без override новый ролик - `unknown`, ожидает классификации.
- Исключить недоступные ролики или корректно показывать fallback с внешней ссылкой, не допускать «пустой страницы» из-за ошибки API. При ошибке синхронизации оставлять последний успешный кэш; ошибку логировать.
- Для `format=short` использовать исходное YouTube embed по ID в вертикальном контейнере (не локальный Shorts-плеер). iframe загружать по клику; предусмотреть отказ сторонних cookies в privacy тексте.
- Типы данных: `youtubeId`, `title`, `description`, `thumbnail`, `publishedAt`, `durationSeconds`, `format (video|short|unknown)`, `memberships: [{level,section,playlistId,position}]`, `isEmbeddable`, `youtubeUrl`, `lastSyncedAt`.
- Статический сайт хранит JSON snapshot и не сбрасывает его при ошибке API. Названия плейлистов для интерфейса - согласованный текст, а не слепо импортированное заглавие плейлиста.

### Пример конфигурации
```json
{
  "channelUrl": "REPLACE_WITH_VERIFIED_CHANNEL_URL",
  "sectionPlaylists": {
    "a2-speaking-part-1": "REPLACE_A2_S1",
    "a2-speaking-part-2": "REPLACE_A2_S2",
    "a2-speaking-part-3": "REPLACE_A2_S3",
    "a2-writing": "REPLACE_A2_W",
    "b1-speaking-part-1": "REPLACE_B1_S1",
    "b1-speaking-part-2": "REPLACE_B1_S2",
    "b1-speaking-part-3": "REPLACE_B1_S3",
    "b1-writing": "REPLACE_B1_W"
  },
  "shortsIndexPlaylistId": "REPLACE_ALL_SHORTS_OR_NULL",
  "formatOverrides": {
    "SAMPLE_SHORT_VIDEO_ID": "short",
    "SAMPLE_LONG_VIDEO_ID": "video"
  },
  "compilations": {
    "SAMPLE_LONG_VIDEO_ID": ["SAMPLE_SHORT_VIDEO_ID"]
  }
}
```
`shortsIndexPlaylistId = null` означает режим восьми плейлистов + ручная классификация. `formatOverrides` и `compilations` - необязательные объекты; настоящих ID пока нет. **Не публиковать плейсхолдеры в продакшене.**

## 9. Видео-компиляции и связь с Shorts
- Полное видео, в которое смонтированы несколько Shorts, остается **обычным Video** с самостоятельным YouTube ID.
- Каждый исходный Short остается самостоятельной карточкой в группе Shorts. Появление компиляции не удаляет Shorts и не копирует их на сайт.
- Опционально (этап 2) можно хранить `compilations: {longYoutubeId: [shortYoutubeId1,...]}`. Тогда на странице выбранного длинного видео показывать `Short clips in this compilation` с превью и ссылками. Отображать только реальные проверенные связи.
- Запретить автоматическое сопоставление по одинаковым словам в названиях: оно будет давать ложные связи.

## 10. Форма обратной связи
- Публичная страница `/contact/` + блок/компонент на главной. Поля Name, Email, Subject (General question / Suggest a video / Report a problem / Other), Message. Name, Email, Message обязательны.
- Серверная валидация email, длины текста; защита от спама honeypot и rate limiting, при необходимости Turnstile.
- Отправка письма с serverless endpoint или серверной части на email владельца; секреты не хранить в фронтенде; успешно только после подтверждения реальной доставки провайдером.
- Показывать реальный статус Success/Error, не стирать текст пользователя при ошибке.
- Privacy Policy, уведомление о персональных данных, HTTPS; только необходимое хранение персональных данных.

## 11. Визуальная система и адаптивность
- Светлый минимализм; фирменный логотип, цветовая система Elakoo, синие акценты и нейтральные поверхности. Dreaming Spanish - пример удобства каталога, НЕ бренд-копирование.
- Главная: две колонки A2/B1 на desktop; на mobile блок A2, затем блок B1. По 4 карточки.
- **Отдельная геометрия обложек:** Videos 16:9; Shorts 9:16, не растягивать изображения и не обрезать ключевой текст на обложке. Для YouTube thumbnail Shorts при отсутствии портретного изображения допустим нейтральный фон с `object-fit: contain` либо вручную заданная вертикальная обложка (без генерации фейкового кадра).
- Главная и раздел: Videos основная сетка; Shorts ниже в самостоятельной компактной горизонтальной полосе; общий каталог: вкладки.
- Ограничение ширины основного контента примерно 1100-1200px; равномерные отступы, лаконичные карточки, контраст WCAG AA, фокус клавиатуры.
- Контрольные ширины 360, 390, 768, 1024, 1440px; не допускать горизонтальный скролл страницы. Карусель Shorts может горизонтально прокручиваться внутри своего контейнера.
- На мобильном видео 1-2 карточки в ряд, Shorts 2-3 в видимой области карусели; плеер вертикального видео ограничен по высоте.
- Только английский интерфейс на старте. Нет A1/B2/Reading/Listening или терминов `Lesson`, `Course`, `Progress`.

## 12. Производительность, SEO, доступность, безопасность
- SSG/static или гибрид с SSR только по необходимости; серверный/serverless sync YouTube в JSON. Отдельный VPS для хранения видеоконтента **не нужен**.
- Lazy-loading превью, отложенная загрузка iframe до Play, правильные состояния empty/loading/error; отсутствие тяжелой клиентской загрузки 100+ роликов.
- Title, description, canonical, OpenGraph, sitemap.xml, robots.txt, SEO-доступный список категорий и заголовков без обязательного JS API запроса.
- Ссылки открываются осмысленно (внешние YouTube - в новой вкладке с `rel=noopener noreferrer`); поддержка клавиатуры и доступные подписи.
- Метрики: открытие видео на сайте, клики на YouTube, смена вкладок Videos/Shorts, выбор уровня/раздела, отправка формы. С соблюдением privacy.
- HTTPS, безопасные HTTP-заголовки, секреты в env, минимальные права API key, кэш и наблюдаемость ошибок синхронизации.

## 13. Приемочные критерии v1.1
1. Ровно 8 публичных разделов сайта (A2 и B1, по 4); не создается девятый видимый раздел при использовании служебного Shorts-index.
2. Каждая страница раздела показывает ролики именно своего тематического YouTube-плейлиста, включая случаи больше 50 материалов.
3. Длинное видео-компиляция показывается в **Full Videos**, а исходные Shorts - в отдельном **Shorts** блоке; не дублировать длинное видео в Shorts.
4. На главной раздельные Latest Videos (16:9) и Latest Shorts (9:16); в разделе те же отдельные блоки; в `/videos/` **две вкладки**.
5. При режиме 9 плейлистов попадание/исключение из служебного Shorts-index влияет на формат после синхронизации; без лишних правок сайта.
6. При режиме 8 плейлистов неизвестный новый ID не классифицируется молча неверно и доступен для простой ручной классификации.
7. Один Short из двух тематических плейлистов показывается в обоих разделах и один раз в общем каталоге.
8. Имеется встроенный просмотр обоих форматов и внешняя ссылка на конкретный YouTube-ролик и тематический плейлист.
9. Latest сортируется по `publishedAt`; в разделе доступен порядок оригинального тематического плейлиста.
10. При ошибке YouTube API остается последний успешный каталог, а в логе есть диагностика.
11. Форма отправляет реальный email, обрабатывает ошибки, имеет валидацию и антиспам.
12. Desktop и mobile корректны; Shorts действительно портретные, карусель работает мышью и на касание.
13. Не показываются A1/B2/Reading/Listening, тесты и личный кабинет.
14. Нет фиктивных кнопок, макетных ID в production и сломанных ссылок; Privacy/SEO/HTTPS настроены.
15. Исходный код, README, конфигурация ID и инструкции по публикации/синхронизации переданы заказчику.
16. При заданном `compilations` корректно отображаются связи, либо, если этап 2 не включен, связи не выдумываются.
